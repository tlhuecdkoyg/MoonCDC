# MoonCDC 运行自查与修复记录（2026-11-07）

本轮在 0.2.0 基线上复跑验证，并使用独立 SQLite 连接、并发进程及异常输入检查未覆盖的边界；首轮修复版本为 **0.3.0**，后续交叉检查的补丁版本为 **0.3.1**。

| 已复现问题 | 处理结果 |
| --- | --- |
| 过滤目标漏传计划时可能先补齐源端确认 | 普通同步在任何确认前拒绝过滤目标，正确传入计划后可恢复 |
| 无穷值写入后生成不可消费事件，阻塞后续日志 | 捕获触发器以 ABORT 拒绝整条写语句，数据和日志均回滚 |
| 后加业务触发器可能使 UPDATE 事件先于 INSERT | 拒绝源表的其他触发器，检测新增触发器并阻止受影响写入 |
| 非法 UTF-8 TEXT 被底层绑定转码，快照和审计漏报 | 先读取原始 UTF-8 字节再严格解码；异常会失败且不登记/推进消费者 |
| 合法 TEXT 开头的 BOM 在 UTF-16 绑定时被 SQLite 剥除 | 参数以 UTF-8 BLOB 绑定并在对应参数位置 CAST 为 TEXT，值不插入 SQL 文本 |
| 负零在部分列类型仍保留，但捕获无法识别其符号 | 将数据库零规范化契约写明并统一快照与事件；核心 wire 仍保留符号 |
| CLI/诊断只显示错误类型，缺少实际原因 | 输出捕获、参数、SQLite 约束和编码错误的具体消息 |
| 直接构造的过滤对象可以绕过序列化预算 | 编码也限制深度和宽度，并拒绝递归引用形成的循环 |

## 验证方式

0.3.0 本地验证结果：原生后端 **41/41**，JavaScript 与 wasm-gc 各 **14/14** 通过；原生构建、原有集成测试、5,134 样本 REAL 回归及 200 次提交并发测试均通过。有效生产 MoonBit 代码为 **4,547 行**，统计口径见仓库脚本；这些结果不等同于赛事官方验收结论。

- `python scripts/verify.py`：格式、编译、native/JS/wasm-gc 适用测试、API 生成差异、代码统计及独立进程验证。
- `scripts/real_regression.py`：5,134 个有限 REAL 样本的非零位模式与实际数据库值比较；正负零的数据库规范化另有独立回归。
- `scripts/concurrency_regression.py`：200 次外部提交、两个共享消费者的同步任务和并发清理；核对全部最终行、类型、源/目标/确认游标、日志连续性及审计。
- 新增回归验证非法 UTF-8、BOM/NUL/emoji、负零、非有限数整句回滚、额外触发器、漏传计划及旧捕获升级的幂等性和状态保持。
- 畸形 JSONL 的头尾、计数、顺序、游标、行宽及非法值，以及深嵌套 JSON，均要求在目标数据和游标变化前拒绝。

## 升级与适用边界

0.3.0 支持在维护窗口对完整的 0.2.0 捕获执行 `upgrade-capture`，验证后原子替换已知触发器，不重置日志或消费者。未知定义、结构漂移、编码不符及不可解码的历史事件会拒绝升级；该命令不修复历史数据损坏。

数据库捕获支持 UTF-8 数据库和有效 Unicode TEXT，任意字节应使用 BLOB。SQLite 零按规范化后的数值语义处理；要求保留零符号的应用应使用显式二进制表示。源表的其他业务触发器不在支持范围，不能通过删除触发器来忽略其业务含义。完整步骤见 [使用手册](OPERATIONS.md)。

## 针对 0.3.0 的交叉检查

0.3.1 本地验证：原生后端 **47/47**，JavaScript 与 wasm-gc 各 **14/14**，同一全量验证脚本内的原生构建、集成、REAL 逐位回归和并发测试通过；有效生产 MoonBit 代码 **4,552 行**。

- 文本参数内部 CAST 会赋予表达式 TEXT affinity，导致 `1 = ?` 在绑定文本 `"1"` 时从假变真，可能误更新数据。现以 SQLite 无操作的一元 `+` 去除该 affinity，保留 UTF-8 字节绑定和原生参数的比较语义；新增查询、更新、NULL/类型与列 affinity 回归。
- 原先按 DDL 全文查找 `VIRTUAL TABLE` 会误拒绝普通表的同名列、表名或字符串默认值。现读取 SQLite 的实际表类型。常规用例可完成安装、快照、更新、同步与审计；FTS 虚拟表分支仅在运行时实际编译了相应模块时执行。
- 升级失败测试验证：预算不足、坏日志、未知触发器定义均不改变旧触发器、日志、源标识、游标、消费者确认或保留水位；增加预算后可重试成功。
- 外键级联更新/删除、复合 DESC 主键和 WITHOUT ROWID 场景通过。目标新增 UNIQUE 约束导致批内第二条失败时，首条和游标一并回滚，移除外部约束后可重试。
- 独立副本运行 24 个固定种子、每个 180 次变更，比较 raw、相邻压缩、分批/合批/JSONL、过滤与过滤后压缩五种路径；混合类型主键、跨类型主键更新、过滤进出及列重排均无分歧。
- TEMP 业务触发器能绕过持久 main-schema 的触发器枚举；这是不支持的业务触发器场景，现明确由调用方禁止，而不再声称写保护可以完整检测它。

0.3.1 不改变捕获触发器格式；完整 0.3.0 捕获无需再次升级。以上结果限定于实际执行的范围，不代表对所有 SQL、外部组件和任意并发调度作无缺陷保证。
